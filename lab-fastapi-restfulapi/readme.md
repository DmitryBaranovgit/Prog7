# 📘 Отчет по лабораторной работе
## Разработка RESTful API с использованием FastAPI и OpenAPI

### 🔹 Цель работы

Целью являлось изучение принципов разработки RESTful API с использованием фреймворка **FastAPI**, реализации CRUD-операций, валидации данных с помощью **Pydantic**, автоматической генерации документации **OpenAPI**, а также тестирования API через **Swagger UI**

1. **Создание и настройка проекта**

  * Было установлено и настроено окружение с использованием FastAPI и Uvicorn
  * Создан основной файл приложения, инициализирован объект FastAPI

2. **Реализация CRUD-операций**

   * Реализованы основные эндроинты API для работы с книгами: получение списка, просмотр по идентификатору, добавление, обновление (полное и частичное), удаление
   * Для каждой операции определены корректные HTTP-методы (GET, POST, PUT, PATCH, DELETE) и коды состояния

3. **Моделирование данных и валидация**

   * Описана модель данных Book с помощью библиотеки **Pydantic**, обеспечивающая автоматическую валидацию вводимых данных (проверка длины срок, диапазона годов и т.д.)

4. **Фильтрация и пагинация данных**

  * Расширен функционал эндпоинта GET /api/books для поддержки параметров фильтрации по автору и диапазону годов издания
  * Добавлены параметры пагинации (skip и limit) для постраничного вывода списка книг

5. **Добавление статистики**

   * Добавлена простая API-аутентификация с использованием заголовка X-API-key
   * Операция создания, изменения и удаления книг теперь требует наличия корректного ключа доступа

7. **Документирование и тестирование API**

   * Сгенерирована автоматическая документация в формате **OpenAPI**
   * Проверена работа всех эндпоинтов через интерфейс **Swagger UI** (/docs) и **ReDoc** (/redoc)

8. **Ответы на контрольные вопросы**

   * Подготовлены ответы на теоретические вопросы

## 🧾Контрольные вопросы

### 1. Что такое REST и какие шесть принципов лежат в его основе?

**REST (Representational State Transfer)** - это архитекутурный стиль взаимодействия клиент-серверных приложений, использующий стандартные методы HTTP

**6 принципов REST:**

1. **Клиент-серверная архитектура** - разделение интерфейса и логики
2. **Отсутствие состояния (Stateless)** - сервер не хранит контекст между запросами
3. **Кэшируемость (Cacheable)** - ответы могут быть кэшированы
4. **Единообразие интерфейса (Uniform Interface)** - стандартные методы и форматы
5. **Слои системы (Layered System)** - возможность промежуточных серверов
6. **Код по требованию (Code on Demand)** - сервер может возвращать исполняемые код

### 2. В чем разница между методами PUT и PATCH

| Метод     | Назначение                               | Особенность                        |
|-----------|------------------------------------------|------------------------------------|
| **PUT**   | Полностью заменяет ресурс новыми данными | Требует передачу **всего объекта** |
| **PATCH** | Частично обновляет существующий ресурс   | Изменяет **только указанные поля** |

### 3. Что означает идемпотентность HTTP метода?

**Идемпотентность** - свойство операции, при котором повторный запрос дает тот же результат, что и первый

*Идемпотентные методы:* GET, PUT, DELETE, HEAD, OPTIONS
*Неидемпотентные методы:* POST, PATCH

### 4. Какие коды состояния HTTP используются?

**Успешные операции:**
200 OK, 201 Created, 204 No Content
**Ошибки клиента:**
400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict
**Ошибки сервера:**
500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable

### 5. Что такое OpenAPI Specification и для чего она используется?
**OpenAPI Specification (OAS)** - стандарт описания REST API в формате JSON или YAML
Используется для:
* автоматической генерации документации
* тестирование API
* создания SDK и клиентов

### 6. В чем разница между OpenAPI и Swagger?

| Термин      | Описание                                                              |
|-------------|-----------------------------------------------------------------------|
| **OpenAPI** | Спецификация (стандарт описания API)                                  |
| **Swagger** | Набор инструментов, реализующих OpenAPI (Swagger UI, Editor, Codegen) |

### 7. Какие преимущества FastAPI для разработки REST API?

* Высокая произовдительность (асинхронность)
* Автоматическая генерация документации (Swagger, ReDoc)
* Валидация данных через **Pydantic**
* Поддержка аннотаций типов Python
* Простота тестирования и расширяемость

### 8. Что такое Pydantic и как он используется в FastAPI?

**Pydantic** - библиотека для првоерки (валидации) и сериализации данных на основе аннотаций типов Python.

**В FastAPI используется:**

* описания входных и выходных данных
* автоматической валидации запросов и ответов
* генерации схем OpenAPI

### 9. Как FastAPI автоматически генерирует документацию API?

FastAPI строит **OpenAPI-схему** на основе:

* аннотаций типов Python
* моделей Pydantic
* описание маршрутов

### 10. Что такое валидация данных и почему она важна в REST API?

**Валидация данных** - это проверка входных данных на соответствие ожидаемому формату и типам.
Она важная для:

* предотвращения ошибок и уязвимостей
* защита сервера от некорректных данных
* обеспечения надежности API

### 11. Объясните принцип stateless в Rest API

Каждый запрос должен содержать всю информацию, необходимую для обработки.
Сервер не хранит состояние клиента между запросами.
Это делает API более масштабируемым и независимым.

### 12. Какие компоненты входят в структуру OpenAPI документа?

1. openapi - версия спецификации
2. info - информация об API (название, версия, описание)
3. servers - список серверов
4. paths - маршруты (эндпоинты) и методы
5. components - схемы, параметры, ответы
6. security - механизмы аутентификации
7. tags - логическая группировка операций

### 13. Как реализуется обработка ошибок в FastAPI?

Для обработки ошибок используется класс **HTTPException**
**middleware** для глобальной обработки и логирования ошибок

### 14. Что такое HATEOAS и как этот принцип применяется в REST API?

**HATEOAS** (Hypermedia as the Engine of Application State)** - принцип REST, при котором сервер возвращает не только данные, но и ссылки на связанные действия**

Это делает API самодокументируемым и навигационно удобным.

### 15. Какие методы аутентификации можно использовать в REST API?

**API Key** - ключ в заголовке или парметре запроса
**Basic Auth** - логин и пароль
**Bearer Token / OAuth2**
**JWT**
**Session-based**
**OpenID Connect**
