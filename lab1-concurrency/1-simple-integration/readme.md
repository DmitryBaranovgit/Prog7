## 5. Выводы

### 1. Последовательное решение
- **Простое в реализации** - минимальный код, нет сложной синхронизации
- **Линейно масштабируется по `n_iter`** - время пропорционально количеству итераций
- **Для 10^6 итераций время заметно увеличивается** - демонстрирует границы прозводительности однопоточноо подхода

### 2. Многопоточное решение
- **Корректно использует `Thread` и `Lock`** - синхронизация доступа к общей памяти
- **В CPython не дает ускорения из-за GIL** - глобальная блокировка интерпретатора
- **Часто работает медленее**, чем однопоточная версия, из-за:
  - накладных расходов на создание потоков
  - блокировка `Lock`
  - контекстных переключений

### 3. Итоговое сравнение
- **Для CPU-bound задач** (численное интегрирование) -> `Thread` неэффективен
- **Для реального ускорения трубется**:
  - `multiprocessing`
  - или Cython / Numpy / Numba
