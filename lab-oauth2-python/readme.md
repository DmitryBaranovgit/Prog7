# 💻 Практика OAuth 2.0 в Python

## 🌐 Описание
Протокол **OAuth 2.0** и его практическая реалоизация на языке **Python**

1. **Authorization Code Flow** - получение и использование токена доступа (`access token`) для авторизованного запроса к API.
2. **Обновление токена (Refresh Token)** - механизм автоматического продления токена без повторной авторизации пользователя.

## 🎯 Цели работы
- Ознакомиться с архитектурой и ролями участников протокола **OAuth 2.0**
- Научиться получать и использовать **access token** для доступа к защищенным ресурсам
- Реализовать обновление токена через **refresh token**
- На практике применить библиотеку **`requests-oauthlib`** и работу с API Google

## 📖 Теоретические основы

**OAuth 2.0** - это протокол делегирования авторизации, который позволяет сторонним приложениям получать ограниченный доступ к данным пользователя без передачи его логина и пароля.
Он используется в большинстве современных веб-сервисов.

## 🔷 Задание 1. Реализация Authorization Code Flow

В ходе первого задания был реализован процесс авторизации через Google:
1. Приложение перенаправляет пользователя на страницу входа Google
2. После подтверждения доступа Google возвращает **authorisation code**
3. Код обменивается на **access token** и **id_token**
4. Приложение запрашивает данные о пользователе из защищенного ресурса

### 🟢 Результат
После успешного выполнения пользовательские данные возвращаются в формате JSON, включая:
- имя и фамилию
- адрес электронной почты
- ссылку на аватар
- идентификатор Google-профиля

## 🔷 Задание 2. Обновление токена (Refresh Token)

Во втором задании реализован механизм **обновление токена**:
- При первой авторизации выдается **refresh token**, который сохраняется в файл `token.json`
- При последующих запусках программа использует этот refresh-токен для получения нового access-токена
- Таким образом, повторная авторизация через браузер не требуется

## 📄 Ответы на вопросы

1. Основные роли в OAuth 2.0 и их функции
- Resource Owner - владелец данных, предоставляющий доступ
- Client - приложение, которое запрашивает доступ к данным пользователя
- Authorization Server - сервер авторизации, проверяет учетные данные и выдает токен
- Resource server - сервер, где хранятся защищенные ресурсы и который проверяет токены доступа

2. Authorization code

Authorization code - это временный код, который приложение получает после успешной авторизации пользователя.
Он используется для безопасного обмена на **access_token** без передачи пользовательских данных (логина и пароля)

3. Почему параметр state важен в запросе на авторизацию?

Параметр **state** защищает от атак типа CSRF.
Он позволяет убедиться, что ответ от сервера авторизации действительно связан с исходным запросом клиента

4. Чем отличается Authorization Code Flow от Client Credential Flow?

- **Authorization Code Flow** - используется, когда доступ запрашивается от имени пользователя (включает взаимодействие с браузером).
- **Client Credential Flow** - применяется, когда приложение получает доступ от собственного имени (без участия пользователя), например для внутренних API-запросов.

5. В каких случаях используется refresh token и его роль?

**Refresh token** используется, когда срок действия **access_token** истекает.
Он позволяет приложению получить новый **access_token** без повторной авторизации пользователя, обеспечивая непрерывный доступ к API.
